# Testa dig själv — Markdown & README

Utan att kolla:

1. Vilka fyra saker bör en bra README innehålla?

<details markdown="block">
<summary>Visa svar</summary>

Vad projektet är, hur man kör det, vad man behöver (förutsättningar), och vem som gjort det (plus eventuell licens).

</details>

2. Är Pull Request en Git-funktion eller en GitHub-funktion?

<details markdown="block">
<summary>Visa svar</summary>

En GitHub-funktion. Git självt har inget koncept som heter "Pull Request" — det är ett granskningsverktyg GitHub (och liknande tjänster) byggt ovanpå Git.

</details>

3. Vad är regeln för en bra PR-beskrivning, samma regel som för commit-meddelanden?

<details markdown="block">
<summary>Visa svar</summary>

Förklara varför, inte bara vad — koden visar redan vad som ändrades, beskrivningen ska ge kontext en granskare inte kan se i diffen.

</details>
